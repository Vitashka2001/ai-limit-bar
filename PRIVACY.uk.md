# Приватність

[English](PRIVACY.md) · [Українська](PRIVACY.uk.md) · [Русский](PRIVACY.ru.md)

AI Limit Bar працює на Mac користувача й не звертається до жодного власного сервера.

Застосунок:

- не збирає аналітику або телеметрію;
- не використовує власний сервер;
- не читає й не зберігає паролі, cookies, session storage або API-ключі;
- не запитує доступ до введення з клавіатури, запису екрана, мікрофона, камери або файлів користувача;
- отримує обліковий запис і ліміти Codex через локальний `codex app-server`;
- коли ввімкнено **Автооновлення Claude**, запитує ліміти Claude в Anthropic через `api.anthropic.com/api/oauth/usage`, використовуючи вхід самого Claude Code, як описано нижче;
- отримує відсотки лімітів Claude Code і час їх скидання через офіційний локальний інтерфейс `statusLine`;
- може пасивно читати локальний кеш Claude Desktop `plan-usage-history.json` із відсотками, часом оновлення та несекретним ID організації;
- може пасивно читати запис `cachedUsageUtilization`, який сам Claude Code зберігає в `~/.claude.json`, із відсотками, часом скидання та несекретним ID облікового запису. Решта цього файлу не використовується.

## Живі ліміти Claude

Локальні кеші Claude оновлюються лише приблизно раз на промпт, тож під час довгої роботи агента вони стоять на місці. Щоб показувати актуальні цифри, AI Limit Bar приблизно раз на хвилину запитує Anthropic напряму — тим самим запитом, що й команда `/usage` у Claude Code.

Для автентифікації цього запиту AI Limit Bar читає елемент `Claude Code-credentials` зі зв'язки ключів входу через `/usr/bin/security` — той самий інструмент, яким Claude Code його зберігає, тому діалог зв'язки ключів не з'являється. Елемент перечитується перед кожним запитом, бо Claude Code замінює його щоразу, коли оновлює вхід. З цього елемента використовується лише access token: він тримається в пам'яті на час одного запиту й надсилається лише на `api.anthropic.com`. Refresh token із того самого елемента ніколи не використовується: оновлення входу тут ротувало б його повз Claude Code і розлогінило б Claude Code. Коли access token прострочено, живі запити призупиняються, доки Claude Code його не оновить, а замість них показуються локальні джерела нижче. Нічого з елемента не записується на диск і не потрапляє в журнали.

Відповідь містить лише відсотки використання та час скидання; AI Limit Bar тримає останню з них у пам'яті й не записує її на диск. Якщо Anthropic відповідає обмеженням частоти, застосунок чекає стільки, скільки просить сервер, збільшуючи паузу до 15 хвилин.

Вимкнення **Автооновлення Claude** повністю зупиняє ці запити.

## Локальні джерела Claude

Коли ввімкнено **Автооновлення Claude**, AI Limit Bar також додає команду до `~/.claude/settings.json` разом з офіційною опцією Claude Code `refreshInterval`, тому рядок стану перезапускається кожні 30 секунд, поки відкрита термінальна сесія. Claude Code передає їй звичайний JSON рядка стану. AI Limit Bar зберігає лише відсотки двох лімітів, час їх скидання, час отримання й останньої зміни. Session ID, шляхи проєктів, запити, відповіді та контекст моделі не зберігаються.

Кеш Claude Desktop не містить email, типу плану або часу скидання, тому AI Limit Bar бере їх з інших джерел. Усі джерела об'єднуються по вікнах, перемагає найсвіжіше значення. Дані залишаються видимими й беруть участь у виборі індикатора незалежно від віку, бо ліміт не змінюється, поки Claude простоює; вікно, час скидання якого минув, знову показується порожнім. AI Limit Bar не запускає, не приховує й не завершує Claude Desktop.

Щоб вирішити, який сервіс показувати, AI Limit Bar запам'ятовує у власних налаштуваннях останні побачені відсотки кожного сервісу та час, коли вони востаннє зросли.

## Інше

Під час зміни облікового запису Codex відкривається офіційний процес авторизації в браузері. Новий обліковий запис стає активним для інших локальних інструментів Codex на цьому Mac.

Користувач може зупинити все опитування через **Моніторинг лімітів** або закрити застосунок через **Повністю вимкнути**.
